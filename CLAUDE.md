# TechnoGid — память проекта для Claude

Читай этот файл первым делом в начале любой новой задачи по этому репозиторию.
После каждой публикации (сайт или Дзен) — обновляй раздел «Статус» ниже.

## Назначение проекта

Контент-проект **techno-gid.ru** — сайт-агрегатор обзоров гаджетов, электроники
и автотоваров (на движке GitHub Pages, статический HTML). Материалы адаптируются
и кросспостятся в Яндекс.Дзен и Telegram (@technogid_ru). Часть тем сопровождается
короткими вертикальными видео (Shorts/VK Клипы), которые генерируются во внешних
инструментах (Gemini Notebook и т.п.) и обрабатываются здесь (обрезка заставки,
замена водяного знака на плашку TechnoGid через ffmpeg).

## Структура репозитория

- `index.html` — главная, карточки статей в блоках `.featured-grid`.
- `sitemap.xml` — карта сайта, каждая опубликованная статья должна быть и здесь,
  и на главной. URL в sitemap обязаны совпадать с реальными именами файлов —
  раньше тут были 2 битые ссылки (обнаружено и исправлено 24.09.2026).
- `style.css` — общие стили. Основной класс для картинок внутри статьи —
  `.article-figure img` (обязательно `width:100%; height:auto;`, иначе картинка
  тянется — был баг, исправлен 24.09.2026).
- `articles/*.html` — HTML-статьи самого сайта techno-gid.ru. Шаблон — смотри
  на `local-game-streaming-guide.html` или `powerbank-buying-guide-2026.html`
  как на образец полной структуры (header/meta, article-figure, affiliate-card,
  verdict-box, related-posts, footer).
- `content/dzen/*.md` — адаптации статей под Яндекс.Дзен (более короткий текст,
  markdown, картинки — **абсолютные ссылки** вида
  `https://raw.githubusercontent.com/lebserval-art/lebserval-art.github.io/master/images/...`,
  никогда не относительные пути — Дзен их не увидит).
- `content/telegram/*.md` — готовые посты для Telegram (@technogid_ru), по одному файлу на статью.
- `images/<тема>/*.jpg|svg` — картинки статей. Для новых материалов с фото
  (не SVG-иконками) заводи отдельную подпапку `images/<slug-темы>/`.
- `images/dzen/<тема>/` — исторически использовалась под картинки конкретно
  для Дзен-адаптаций (см. `images/dzen/local-streaming/`). Для новых материалов
  можно класть картинки в общую `images/<slug>/` и переиспользовать те же файлы
  и для сайта, и для Дзен (raw-ссылкой) — так делали для powerbank-2026.
- `zigbee-starter-guide.html`, `about.html`, `contacts.html`, `privacy.html` —
  страницы в корне репозитория (не в `articles/`).
- `EXPERIENCE.md` — редполитика («Анти-робот») и подтверждённый реальный опыт автора; читать перед написанием текстов. «Драматургия от боли» строится либо на фактах из этого файла, либо на реальных жалобах/отзывах покупателей (с пометкой «по отзывам»); выдуманных историй от первого лица нет. **Репозиторий публичный — не писать туда имя, город, семью.**
- `CNAME` — домен techno-gid.ru. **Не трогать, не удалять, не редактировать.**

## Правила

1. **CNAME не трогать.** Файл в корне репозитория, содержит только `techno-gid.ru`.
2. **Разметку сохранять.** Новые статьи собирать по образцу существующих
   (`local-game-streaming-guide.html` / `powerbank-buying-guide-2026.html`),
   переиспользовать те же CSS-классы, а не изобретать новые без необходимости.
3. **Видео в репозиторий не класть.** GitHub — жёсткий лимит 100 МБ/файл,
   Git LFS не установлен. Обработанные ролики (обрезка/плашка) отдаются
   пользователю напрямую файлом в чат, в git не коммитятся.
4. **Каждая новая статья на сайте** должна быть прописана в двух местах:
   `index.html` (карточка в `.featured-grid`) и `sitemap.xml` (новый `<url>`).
   **Никогда не добавлять карточку скриптом, который слепо ищет
   `<main class="container">` (или любую другую подстроку) и вставляет
   HTML сразу после неё** — при малейшем изменении разметки (например, класс
   `<main>` стал `class="container home-main"`) это либо молча ломается,
   либо втыкает карточку не в тот блок и расслаивает структуру страницы.
   Новую карточку дописывать в конец соответствующего блока карточек
   (`.featured-grid` или `.grid`) вручную/через Edit, в том же дизайне
   (`class="card"` со всеми вложенными `card-img/card-body/card-tag/
   card-title/card-desc/card-footer`), одним куском вместе с остальной
   правкой файла. Из-за такого скрипта (`add_tv_box_article.py`) 24.09.2026
   в проекте завели ложную тревогу о «расслоившейся» разметке index.html —
   сам скрипт удалён.
5. **Партнёрские ссылки без реальных erid-кодов** — если нет готовой партнёрской
   ссылки на конкретную модель, ставить ссылку-поиск на Маркет/AliExpress и
   явно помечать в `affiliate-disclaimer`, что ссылку нужно заменить перед
   монетизацией. Не выдумывать erid/рекламные коды.
6. **Дзен-картинки — только абсолютные raw.githubusercontent.com ссылки**,
   без плейсхолдеров вида `[МЕСТО ДЛЯ СКРИНШОТА]` к моменту публикации.
7. **Verification-меты в `<head>` index.html — не трогать без понимания, зачем
   их несколько.** Разные `yandex-verification` — это не всегда дубли одного
   и того же: `3a8dea59f358f04c` — текущая верификация Яндекс.Вебмастера
   (стоит на index.html и в большинстве статей), `sw856fm90wqwnpxc` — код для
   **Яндекс.Дистрибуции** (другой продукт, подтверждено HTML-комментарием в
   истории коммитов), это не дубль и трогать его нельзя. Легаси-код
   `6pjcg0idg6kg6ho5` (с проверочными файлами `6pjcg0idg6kg6ho5.html` и
   `yandex_6pjcg0idg6kg6ho5.txt` в корне) удалён из meta 24.09.2026 как
   вытесненный — сами проверочные файлы в корне не трогали, они безвредны.
   Два разных `mitgo-verification` (`d9a7e757...`, `5cf5b0d8...`) — какой из
   них актуален, определить по репозиторию нельзя (это верификация домена во
   внешнем сервисе, аккаунт которого не виден отсюда) — **не удалять ни один
   без прямого подтверждения Сергея**, какой код сейчас активен в кабинете
   Mitgo.

## Регламент подготовки публикаций

При написании или существенном обновлении ключевой статьи готовим комплект:

1. **Версия для сайта** — HTML в `articles/` (+ карточка в `index.html` и `<url>` в `sitemap.xml`, правило 4).
2. **Дзен** — адаптация в `content/dzen/<название>.md` (30–50% объёма, картинки только абсолютными raw-ссылками, партнёрские ссылки с плашками «Реклама»).
   **Перед написанием — проверить через браузер, нет ли уже в канале «Техногид» (dzen.ru/technogid_ru) статьи на эту тему** (дубли не публикуем; если есть — обновляем/дополняем, а не пишем заново).
3. **Telegram** — пост в `content/telegram/<название>.md`:
   - **строго до 950 знаков** (лимит подписи к альбому — 1024, держим запас; считать вместе со ссылками и плашками);
   - в шапке файла (HTML-комментарием) — список рекомендуемых фото из `images/` в порядке показа и raw-база;
   - сам текст — после строки `--- ПОСТ ---`;
   - 2–3 партнёрские ссылки с маркировкой (Маркет — «Реклама. ООО «Яндекс Маркет», ИНН 9704254424»; Али — с `erid`) и ссылка на статью на сайте;
   - без выдуманного опыта и цен, формулировки «по данным карточки».

Имя файла Дзена и Telegram совпадает со слагом статьи. После публикации — обновить «Статус».

## Проверка актуальности моделей

Существование модели, подтверждённое веб-поиском, — не гарантия, что это
актуальная (последняя) версия товара: веб-поиск часто находит старые обзорные
статьи про прошлогодние модели (случай с OBD2-сканерами 24.09.2026 — несколько
моделей в черновике оказались прошлогодними/снятыми с продажи, хотя факт их
существования подтверждался веб-поиском).

- Модели в статье считаются **черновыми** до сверки с реальной карточкой товара
  на целевой площадке (Яндекс Маркет / AliExpress) — эту сверку делает Сергей
  или Claude в чате проекта, обычно на этапе генерации партнёрских ссылок.
- В отчёте по статье явно указывать: **«список моделей черновой, требует
  сверки с витриной»** — до момента, пока сверка не пройдена.
- Для тем с быстрой сменой поколений (телефоны, ТВ-боксы, экшн-камеры и т.п.)
  в ТЗ отдельно отмечать: **«поколение уточнить отдельно, не полагаться на
  дефолтный выбор модели»**.

**Постоянное разрешение автора (09.10.2026):** когда статья полностью согласована по тексту и фото, выполнять полный цикл под ключ — сайт → Дзен → Telegram — без промежуточных подтверждений на отправку. До согласования текста и фото — не публиковать.

## Рабочая ветка и деплой

- Рабочая и единственная используемая ветка — **`master`**. Коммиты и пуши —
  напрямую в `origin/master`, без промежуточных PR (по явной договорённости
  с пользователем).
- GitHub Pages раздаёт сайт **из `master`** (подтверждено через GitHub API:
  `default_branch: master`, `has_pages: true`, плюс статья
  `powerbank-buying-guide-2026.html` существует только в `master` и уже была
  видна пользователю живьём на techno-gid.ru).
- В репозитории есть ещё ветка **`main`** — она расходящаяся/устаревшая
  (меньше файлов, другая история коммитов), на сайт не влияет. Не путать,
  не мержить бездумно, не использовать для новых коммитов.
